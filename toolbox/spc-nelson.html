SPC and Nelson rules for inter-batch monitoring

Phase I baseline, frozen limits, eight detection rules.

spc
methods
Published

May 4, 2026

Statistical process control applied to inter-batch data is not the same thing as real-time SPC on a production line. The rhythm is different, the signal is different, and the failure mode you are trying to catch is different.

This page describes the Phase I / Phase II framework as used in this site, and the eight Nelson rules as implemented in machinelogR.

The core idea

A control chart answers one question: is this batch consistent with the reference population?

To answer it, you need two things. A reference population (Phase I). And a set of rules that define “inconsistent” (Nelson, or Western Electric).

The order matters. Limits are computed once, on data you believe is stable. Then they are frozen. Everything that follows is compared against those fixed limits.

Why freeze the limits?

A chart that recalculates its limits as new data arrives cannot detect a gradual drift: the limits drift with the process and the signal disappears. Phase I limits are established on a stable reference population and held fixed. This is the central principle of Phase I / Phase II SPC.

Introduction to Statistical Quality Control, Montgomery, 8th ed., Ch. 5.

Phase I – establishing the baseline

Phase I is not a burn-in period. It is a deliberate selection of batches that represent what “stable and controlled” looks like for this process.

The output is a set of control limits: center line (CL), upper control limit (UCL), and lower control limit (LCL), computed as CL +/- 3 standard deviations of the Phase I data.

bl_pump <- spc_baseline(phase1_data, variable = "pump_load", time_col = "batch_date")

spc_baseline() returns a list with CL, UCL, LCL, and sigma – the frozen reference. It is computed once and passed explicitly to Phase II.

Three decisions go into Phase I:

Which batches. They must represent normal operation. Batches with known anomalies, equipment changes, or formulation adjustments should be excluded. The number is a balance between statistical stability (more is better) and practical availability (you may only have ten validated batches at launch). Fifteen is a reasonable minimum for inter-batch SPC.

Which variable. A summary statistic per batch, not a time series. Mean, maximum, standard deviation – the choice depends on what the signal is supposed to capture. Maximum product temperature for collapse risk. Mean pump load for gradual mechanical wear. The choice is made before running the chart, not after.

When to re-baseline. Never without justification. A validated change (equipment replacement, formulation update, process improvement) is a valid trigger. Data drift is not: if the process is drifting, re-baselining hides it.

Phase II – monitoring with Nelson rules

Phase II applies the frozen limits to each incoming batch and evaluates it against a set of pattern rules.

Nelson rules were formalized by Lloyd S. Nelson in Journal of Quality Technology (1984, Vol. 16, No. 4) as an extension of the original Western Electric Statistical Quality Control Handbook (1956). Montgomery summarizes them in Introduction to Statistical Quality Control (Ch. 5).

The eight rules

Rule Condition Signal detected
R1 1 point beyond +/-3sigma Acute anomaly
R2 9+ consecutive points on the same side of CL Persistent bias
R3 6+ consecutive points strictly monotone Trend
R4 14+ consecutive points alternating up/down Systematic oscillation
R5 2 out of 3 consecutive points beyond +/-2sigma (same side) Slow drift
R6 4 out of 5 consecutive points beyond +/-1sigma (same side) Moderate drift
R7 15+ consecutive points within +/-1sigma Variance collapse (hugging)
R8 8+ consecutive points outside +/-1sigma (both sides) Bimodality

The “signal detected” column is not in the original Nelson paper – it is a translation of the statistical condition into the process phenomenon each rule is designed to catch. R1 catches abrupt jumps. R5 and R6 catch gradual drifts that would never breach R1. R7 catches a suspicious reduction in variability, which can indicate a stuck sensor, a batch population that has narrowed artificially, or a process that has lost its natural variation.

Rules are not interchangeable. The choice of which rules to apply depends on the degradation mode you are monitoring for.

Selecting rules for a signal

Degradation mode Recommended rules Rationale
Abrupt failure R1 Single point breach is sufficient
Gradual mechanical wear R5, R6 Slow drift, never reaches 3sigma
Process mean shift R1, R2 Jump then persistence
Sensor drift R3, R5 Monotone or asymmetric drift
Sensor failure (stuck) R7 Variance collapses
Mixed or unknown R1 + R5 Pragmatic minimum

The pump load scenario in the equipment-drift detection chapter uses R5. A degrading pump shows a slow, asymmetric increase in load over dozens of batches that never reaches 3-sigma until the equipment is already well into its failure trajectory. R5 was designed for exactly this.

machinelogR – spc_chart()

chart <- spc_chart(
  data     = metrics,
  variable = "pump_load",
  time_col = "batch_date",
  rules    = 5L,          # Nelson R5
  cl_from  = bl_pump      # Phase I baseline (frozen)
)

spc_chart() accepts a scalar or vector of rule numbers. rules = c(1L, 5L) applies both R1 and R5. All eight rules are implemented.

The return value is a list:

chart$violations     # tibble: date, index, rule fired
chart$control_limits # list: CL, UCL, LCL, sigma
chart$n_violations   # integer
chart$plot           # patchwork: I-chart + MR chart

The separation between cl_from (Phase I baseline) and data (Phase II input) is structural, not optional. Passing the same data to both would defeat the purpose.
